# NEXUS 賽局研究所 · Worlds 2026

每日同步 Riot 官方賽程的本機預測網頁，提供比分推演、Key Player 觀察與獨立的歷史玄學評估。繁體中文、深色電競介面，支援手機與桌面。僅呈現真實官方對局；未知對手顯示 TBD。v2 不載入賠率，也不提供自訂對戰。

## 本機使用

需求：Node.js 20 或以上。零第三方執行依賴，不需要帳號或 API Key。

```sh
npm start
```

開啟 [http://127.0.0.1:4196/](http://127.0.0.1:4196/)。只監聽 loopback，沒有公開網站部署。GitHub 公開的是原始碼與公開賽程摘要。

```sh
npm run update:schedule
npm run update:schedule -- --force
npm test
```

第一個命令遵守每日更新視窗，第二個立即重抓。PowerShell 可設定 `$env:PORT = '4197'` 後換埠啟動。

## 每日更新

- 固定來源：[Riot Worlds 官方賽程](https://lolesports.com/en-US/leagues/worlds)。只解析公開頁面的 JSON 結構，不執行遠端 JavaScript，不使用私人 API、登入資訊或 API Key。
- 台灣時間每天 **06:00** 為更新邊界。Local 啟動時與每分鐘檢查當日是否已成功同步或嘗試更新，每個視窗自動嘗試一次。程式關閉時不會在電腦背景執行；重啟會補做尚未執行的視窗。失敗後保留資料，下個每日視窗再試，也可手動立即重抓。
- GitHub Actions 每日 UTC 22:00 執行（台灣隔日 06:00），可手動觸發。GitHub 排程可能延遲。只提交通過驗證的 `data/schedule.json` 與 `data/prediction-history.json`。Local 有自己的官方賽程更新流程，公開模型歷史則從固定 GitHub 來源每小時同步至忽略提交的快取。
- 開著的網頁每分鐘只讀本機 API，取得最新快照與更新狀態；瀏覽器請求不會觸發爬蟲。
- v2.1 的公開模型封存只由 main 的正式 CI 建立，生成及推送前都須距開賽超過十分鐘。各次基準保持不可覆寫，驗證採同場同模型的最後一份合格賽前紀錄。
- 本機啟動及每小時下載固定 GitHub 公開紀錄至忽略提交的快取；失敗保留上次成功版本。此流程沒有上傳功能，亦不會把本機情境或筆記轉為公開模型紀錄。
- 快照包含官方賽事 ID、UTC 開始時間、對手、BO、狀態、已確認結果及戰力摘要。畫面一律顯示台灣時間 UTC+8。
- 來源分頁不完整時，保留先前確認的真實對局，逐場保留 `observedAt`。來源確認完整時，以當次清單取代舊清單，避免永遠保留已撤下的對局。缺漏資訊不自行補隊伍或虛構場次。
- 對手未知、進行中、已結束、時間已過但狀態未更新、超過 26 小時未再確認，或缺少雙方 Elo 時，不輸出賽前比分。已結束場次顯示經 BO 驗證的官方結果。
- `fetchedAt` 是成功抓取時間，並非官方發布時間；來源未提供發布時間，`sourcePublishedAt` 為 null。`sourceHash` 只標識最新取得的官方頁面，不是所有歷史保留項目的雜湊。

目前數量以網站顯示為準。首次快照包含 40 場已載入的官方對局，**不宣稱涵蓋完整世界賽賽程**。官方改版、分頁或反爬限制可能使更新失敗；畫面會標示失敗／資料待更新，保留最後成功資料。

## 預測與互動

1. 依階段篩選、搜尋隊伍、翻頁，查看官方時間及對戰。TBD 保留時間與 BO，不產生假對手。
2. 綜合分析列出所有合法比分、單一比分機率、系列賽勝方傾向及來源戰力。相同機率會並列；最可能比分與系列賽勝方並非相同概念。
3. 情境滑桿可調整左方隊伍 −100～+100 Elo，觀察自己的 Key Player／BP 假設如何改變比分。預設 0，不改寫官方戰力。
4. Key Player 提供專業角色觀察、轉折點與選手玄學，附名單來源、查核日期及確認程度。C9 官方列出 7 位選手；FUR 部分位置依次級來源；MVK 只有次級名單。先發未確認時明確註記，不虛構個人數據。
5. 玄學可切換黑馬、大賽記憶、氣勢延續，各自給出獨立比分劇本與限制。BO1 使用單局獲勝描述。
6. 收藏真實對局、記錄筆記並匯出 JSON 備份。存在此瀏覽器的 `nexus-worlds-v2` localStorage，沒有上傳端點。v1 示範與自訂資料不遷移至官方賽程。

## 模型方法

```text
p = 1 / (1 + 10^((EloB - EloA - userAdjustment) / 400))
```

以官方 Elo 推估單局 A 方勝率，再於每局獨立、勝率固定的假設下，枚舉 BO1、BO3、BO5 所有合法終局。系列賽勝率為該隊所有獲勝終局的機率總和。模型未以本屆結果校準或回測，沒有命中保證；跨賽區原始勝敗只提供背景，不直接相加。BP、版本、先發、選邊與局間相關性未自動建模。

專業判讀為本站模型與角色觀察，並非真人分析師預測。玄學是主觀觀賽劇本，無命中率，不影響專業模型。

## 賽前封存與賽果驗證（v2.1）

公開的 `data/prediction-history.json` 保存官方隊伍 ID、賽制／時間、來源及戰力觀察時間、模型版本、比分分布和 CI 執行來源；不含私人筆記、收藏或滑桿設定。歷史預測不可改寫，官方賽果更正會新增驗證修訂。

同場同模型只評估最後一份合格公開基準。隊伍順序交換以 ID 正確對照；對手、BO 或開始時間異動則標示不可驗證，不當成預測失準。已結束但沒有賽前封存的比賽，顯示「未封存賽前預測」，不使用最新戰力回填。

對局版本異動後需要新的合格封存；不會挑回已被較新版本取代的舊預測來計分，即使後續賽程再次改回原設定。

對局和雙方戰力均須在 26 小時內由來源重新確認，才可生成基準。舊格式的戰力來源時間保持未知，等待正式抓取；官方戰力的計算時間與來源觀察時間分開呈現。唯讀介面為 `/api/predictions` 與 `/api/evaluations`；瀏覽器不提供任何封存寫入端點。

封存上限為 5,000 筆預測、1,500 筆驗證修訂及 8 MiB，超限拒絕整批更新，不刪除歷史。每日擷取可能錯過臨時確定的對戰，缺漏會如實顯示。Git 歷史與 CI 紀錄提供操作來源追溯，並非外部賽事資訊的密碼學真實性保證。

## 模型健康度（v2.2）

「模型健康度」透過唯讀 `/api/model-health` 顯示已驗證、待賽果、未封存及不可驗證的對局，並列出原因。各模型版本、全部 BO 及個別 BO 分開統計；期間以該分組對局的官方開賽時間為準。官方更正只採最新修訂，同場不重複計數。

每項指標自己的分母達 20 場才顯示比例或平均誤差，仍標示探索性結果。精確比分只計最高機率比分唯一的預測；並列另列。五五波不計勝方方向命中，但可列入機率誤差。Brier 為二元系列賽勝方機率平方誤差；比分 Log Loss 為官方終局的封存機率取負自然對數。兩者越低越好，並非獲利指標。

戰力的「計算時間」與「重新讀取來源時間」分開顯示；重新讀取不代表官方已把最新賽果納入 Elo。近期已結束對局晚於該隊戰力計算時間時，介面提示「戰力尚未反映最新賽果」，並提供近期官方結果對照，不自行加權或改寫封存模型。人工 Key Player 觀察超過七天顯示待複核。

## 結構與驗證

```text
app.mjs                    介面、互動、收藏與本機筆記
model.mjs                  Elo、合法終局、獨立玄學劇本
schedule.mjs               共用驗證、台灣時間與預測可用性
crawler.mjs                限定來源擷取、解析、驗證、原子快照
scripts/update-schedule.mjs 手動／CI 更新入口
data/schedule.json         公開來源的驗證摘要
data.mjs                   人工選手觀察與歷史來源
server.mjs                 loopback 靜態檔案及唯讀 API
.cache/                    不提交的快取、更新狀態及測試暫存
```

`npm test` 使用 Node 內建測試，涵蓋合法比分、機率加總、狀態限制、JSON 解析及欄位排序、來源白名單、回應大小、每日視窗、失敗保留、完整清單取代及 API 邊界。合成資料僅用於測試，不進入產品賽程。

CI 執行語法檢查、測試與差異格式檢查。每日寫入工作只具該 job 的 `contents:write`，不在 PR 執行，checkout 不保存憑證，暫存路徑僅限公開賽程及模型歷史兩個 JSON 檔；推送不覆寫遠端歷史。發布保護會對照原始 checkout commit，連同新建紀錄在提交／推送前重新檢查截止時間。

`npm run check:public` 會檢查候選文字檔的已知密鑰格式及不應公開的路徑，只列檔名和類型，不輸出匹配內容；此檢查不保證識別所有敏感資訊。已加入一般驗證與每日更新 CI。驗收證據見 [v2](DELIVERY-v2.md)、[v2.1](DELIVERY-v2.1.md) 與 [v2.2 交付紀錄](DELIVERY-v2.2.md)。
